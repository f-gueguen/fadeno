# ADR 0022: Toolchain and configuration contract

- Status: Accepted
- Date: 2026-07-12
- Owners: Fadeno maintainers
- Related specifications: [Build and diagnostics](../spec/build-adapters-testing.md), [V1 plan](../roadmap/v1.md)
- Supersedes: None

## Context

V1 needs one reproducible way to locate configuration, run development, build
deployable output, and validate a project. The former V1 toolchain gate blocked implementation until
those names, output ownership rules, and environment precedence were explicit.
Route roots, adapter selection, and their configuration fields remain owned by
later gates and must not leak into this decision.

## Decision drivers

- Stock TypeScript remains the configuration language.
- A command behaves the same from a clean checkout and an existing worktree.
- Generated and deployable output have distinct ownership and cleanup rules.
- Environment loading is deterministic and never silently exports secrets to a
  browser artifact.
- Later route and adapter decisions can add typed fields without adding another
  configuration file or command family.

## Decision

The project root contains exactly one `fadeno.config.ts`. It default-exports a
plain configuration object, normally through `defineConfig`. Named-only exports,
JavaScript config variants, multiple discovered configs, non-plain objects, and
unknown fields are errors. V1-01 initially accepts the empty object; later
decision ADRs add their owned typed fields to the same closed shape.

The supported commands are:

- `fadeno dev` — start the development workflow and own ephemeral `.fadeno/`
  state;
- `fadeno build` — produce deployable `dist/` output transactionally;
- `fadeno check` — validate configuration, source boundaries, generated
  artifacts, types, and diagnostics without producing deployable output.

Package scripts may delegate to these commands but do not create alternate
semantics. Commands run relative to the explicit project root, not the config
file's caller or a guessed monorepo ancestor.

`.fadeno/` is disposable framework-owned state and `dist/` is reproducible
deployable output. A command may replace only its owned directory. Failed work
must not partially replace the last accepted output. Two clean builds over
identical inputs produce byte-identical files and do not rewrite unchanged
generated bytes.

Environment files are optional and loaded in this order: `.env`, then
`.env.local`, then the existing process environment. A later source has higher
precedence; process values are never overwritten. Files are UTF-8 lines using
`KEY=VALUE`, blank lines, and whole-line `#` comments. Keys match
`[A-Za-z_][A-Za-z0-9_]*`; duplicate keys within one file, `export`, interpolation,
multiline values, and malformed quoting are refused. Matching single or double
quotes remove only their outer quotes; no escape or substitution language is
introduced.

All loaded values are server-only inputs. No naming prefix automatically makes
a value browser-visible. A future client artifact must declare and validate an
explicit public-input schema before receiving environment data.

## Alternatives considered

- Multiple config formats: rejected because they multiply loader and typing
  behavior before a consumer needs them.
- Mode-specific implicit environment files: rejected because two-file
  precedence plus explicit process values is smaller and easier to reproduce.
- Put build output under `.fadeno/`: rejected because ephemeral internal state
  and deployable artifacts have different lifecycle and audit needs.
- Auto-export prefixed environment variables: rejected because a prefix is not
  a trust-boundary schema.

## Consequences

- The V1 toolchain gate is resolved and leaves the open-gate ledger.
- V1-02 and V1-05 may add adapter and route fields only through their owning
  ADRs and the same closed typed config.
- Package names and entrypoints remain blocked by DG-V1-01.
- The prototype remains private evidence; it is not the `fadeno` executable.

## Validation

The V1-01 prototype loads only the canonical TypeScript default export, proves
environment precedence and refusal cases, writes only `.fadeno/` or `dist/`,
and produces byte-identical consecutive build output. Repository model checks
require current scope and traceability to cite this ADR instead of an open gate.

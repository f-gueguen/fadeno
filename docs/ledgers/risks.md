# Risk ledger

This ledger tracks current risks that can change implementation order or public
scope. It is not a feature list.

| Risk | Current control | Escalation trigger |
| --- | --- | --- |
| Browser updates destroy user state | ADR 0014 narrows structural reuse; ADR 0045 accepts only current-operation, no-store updates whose relevant preceding document and element layout are proven unaffected, with affected/unknown refusal and native current-truth recovery | Implementation applies an affected, unknown, stale, duplicate, cached, cross-generation, or misrouted update; enhancement overwrites user/browser-owned state; or uncertain mutation recovery resubmits the mutation |
| Browser loading or private decoding weakens native, CSP, or isolation authority | ADR 0047 permits only explicit startup through a generated same-origin module using the renderer-owned request nonce; the current packed gate proves wrong/missing nonce, missing artifact, JavaScript-disabled native controls, rollback, exact browser graph isolation, independently measured byte/depth/count/time limits, cancellation, cross-generation refusal, and redacted decision output | Import starts work implicitly; ordinary application markup gains a script sink; browser code becomes reachable from neutral/Node graphs; a refused module damages native controls; decoder metrics come from input; hostile bytes, identity, credentials, or markup escape into decisions/logs; or private schema becomes a public promise |
| Server update projection diverges from native authority or leaks request evidence | ADR 0048 consumes one native response once, binds exact request/response ownership by opaque object identity, records route/resource/action provenance during construction, and proves packed one-pass execution, authorization/cross-user refusal, redaction, rollback, and stale recovery | Projection reruns application or authorization work; copied, stale, unowned, cross-generation, or cross-user evidence publishes; protected markup, proof, session, owner, submitted value, or failure detail enters a record; or a mutation is repeated during recovery |
| Enhanced navigation prevents native behavior before it can preserve browser or user state | ADR 0049 permits only ordinary same-origin GET links, checks a conservative state predicate before interception and again before commit, keeps correlation separate from opaque server authority, cancels superseded work, and returns refused GET work to native destination/current truth | An ineligible or unsafe link is prevented; stale work commits; transported markup executes; browser correlation grants authorization; partial document/history state becomes visible; or rollback damages native links |
| Enhanced history exposes a URL, document, focus, or scroll from different entries | ADR 0050 uses exact active-chain/entry identity, commit-owned displayed identity, fail-closed unsafe tracking across restart, selected-state revalidation, startup/native-departure restoration rollback, monotonic guarded scroll recording that survives a return to zero, pending-traversal close recovery, destination-entry-before-viewport ordering, replacement recovery after a post-selection commit failure, pre-commit flush, pre-refusal cancellation and newest-traversal suppression, focus with scroll prevention, zero-scroll-only enhanced traversal, and current-URL reload for foreign-chain, malformed, unowned, nonzero-document-scroll, or element-scroll entries | A selected entry displays another entry's document; a failed commit duplicates the selected destination; focus induces unexpected scroll; automatic restoration races startup, departure, recovery, close, or commit; pending scroll escapes its displayed entry or restart; a final flush erases unsafe ownership; bounded tracking forgets unsafe ownership; application state changes during a request; destination scroll overwrites the outgoing browser position; history writes exhaust browser limits or cross traversal ownership; numeric scroll is restored without unchanged-layout proof; an older traversal survives newer native recovery; or a late traversal publishes |
| Handler extraction is too magical or too narrow | ADR 0015 accepts only the bounded corpus and conservative refusal; implementation stays V3 | Useful interactions require hidden hydration or broader capture than the accepted contract |
| Security semantics drift behind runtime work | Each trust boundary ships with threat and negative tests | A boundary is implemented without size, origin, authorization, and logging behavior |
| External decoder failures escape classification or resource bounds | The A0-09 threat inventory and fixed-seed `check:a0-decoder-fuzz` gate exercise fourteen exact production surfaces twice with accepted/refused controls, declared per-surface input bounds, a child-process deadline, complete classifications, deterministic digests, and an action-response secret canary | A supported public input reaches an unreviewed parser, produces an internal failure instead of a stable refusal, exceeds its declared bounds, changes between identical replays, or leaks submitted bytes |
| Native action replay or protected-session identity crosses its supported owner | ADR 0035 binds bounded single-use proofs to action/route/generation/session, selects exact-origin POST, encrypted host-only cookies, absolute expiry and privilege rotation, and explicitly limits V1 action serving to one process; V1-13 integrates that owner through focused public-runtime and packed three-browser evidence | A replay entry or session decision crosses processes without an atomic owner; a stolen credential needs immediate revocation; an action runs before complete boundary acceptance; or a later change weakens cleanup, redaction, key, expiry, origin, redirect, or rotation evidence |
| Revalidation regresses beyond its accepted cost | ADR 0020 and the immutable H4 workload baseline remain regression gates; V1-11 reruns every active dependency and proves removing unsafe `keeps` removes no correctness read | Runtime integration exceeds locked latency/query/memory controls or makes correctness depend on `keeps` |
| Resource caching crosses request or authorization ownership | ADR 0034 permits only a fresh request-owned promise map; V1-11 implements bounded framework-owned structural input identity, response-lifecycle cleanup, cross-authorization packed evidence, failure recovery, cancellation, and refusal of every cross-request result-cache policy | A result, failure, key, or dependency survives request completion; authorization or representation affects a value without request isolation; or V1 adds shared caching without a superseding decision and isolation proof |
| Documentation contradicts executable behavior | One authority order, generated guides, and the V1-14C current-packed documented-command replay | A public example or spec cannot be derived from tested source, or a documented command succeeds only through workspace/private state |
| Automated accessibility evidence is mistaken for complete qualification | V1-14D tests the engine-portable native semantic, focus, activation, label, and error-association baseline with JavaScript disabled and records the remaining manual/assistive-technology work explicitly | An automated browser check is presented as proof of focus visibility, user-preference behavior, or assistive-technology usability |
| Independent usability evidence is fabricated, coached, selected, or privacy-invasive | ADR 0043 records the first alpha as `deferred-unqualified` and preserves ADR 0042's frozen tasks, two-non-contributor minimum, exact-artifact identity, all-attempt retention, bounded anonymous records, and synthetic refusal for later collection; A0-07B1/B2 retain replay, reconstruction, privacy, and closed-file-set controls | A release treats unavailable attempts or automation as user success; omits failed attempts; changes tasks after observation; treats facilitator help as independent success; lacks exact artifact identity; retains unreferenced bytes; or retains names, contact details, secrets, paths, or unrelated command history |
| Package surface grows before consumers exist | Public packages require an ADR and demonstrated consumer; ADR 0046 accepts one `./browser` facade, and ADR 0047 fixes its minimum explicit symbols only after disposable and current-packed consumers prove topology, execution, fallback, and one pending minor Changeset | A package or subpath exists only to mirror an internal diagram, browser code becomes reachable from `.`, `./node`, or server/compiler graphs, a second browser version owner appears, or implementation changes the package without reviewed release intent and executable consumer evidence |
| Scope exceeds maintainable capacity | Outcome gates precede tooling and adapter breadth | Work begins on optional tooling before the first vertical slice passes |
| Registry or publication identity drifts | ADR 0037 selects `@fadeno/framework`, the exact export/bin map, public-source provenance, and trusted-publisher identity; ADR 0044 reconciles the registry-mandated `latest` alias with the intended `alpha` channel, requires both to resolve to the exact first alpha, records zero active tokens and no hosted bootstrap secret after maintainer-owned cleanup, and binds later transport to the exact trusted publisher; V2-11A must accept the later-alpha alias policy and V2-11B must separate version-aware current gates from immutable first-alpha evidence before V2-12 publication | Package/source/workflow identity diverges, historical alpha.1 proof is rewritten as current state, either alias moves independently without the accepted later-alpha policy, another channel appears, provenance changes, a credential survives bootstrap, the trusted publisher drifts, or publication occurs before the accepted release boundary |

| Project creation escapes its declared root or drifts from production | ADR 0039 requires a missing target, symlink-free parent path, exclusive target-directory claim, fixed contained allowlist, rollback, exact executing-package version, and the existing compiler/runtime; the packed generated consumer passes check/build/dev/start from the current tarball | A scaffold overwrites existing work, traverses or follows a link, leaves an accepted partial target, contacts a network, or passes without the packed generated consumer |

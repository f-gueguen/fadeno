# Risk ledger

This ledger tracks current risks that can change implementation order or public
scope. It is not a feature list.

| Risk | Current control | Escalation trigger |
| --- | --- | --- |
| Browser updates destroy user state | ADR 0014 narrows structural reuse; DG-V2-01 must own affected scroll | V2 proceeds without explicit scroll management or patch-boundary refusal |
| Handler extraction is too magical or too narrow | ADR 0015 accepts only the bounded corpus and conservative refusal; implementation stays V3 | Useful interactions require hidden hydration or broader capture than the accepted contract |
| Security semantics drift behind runtime work | Each trust boundary ships with threat and negative tests | A boundary is implemented without size, origin, authorization, and logging behavior |
| Revalidation regresses beyond its accepted cost | ADR 0020 and the immutable H4 workload baseline V1 implementation | Runtime integration exceeds locked latency/query/memory controls |
| Resource caching crosses request or authorization ownership | ADR 0034 permits only a fresh request-owned promise map, uses bounded framework-owned structural input identity, refuses application key callbacks and every cross-request result-cache policy, and requires expected/unexpected failure plus next-request recovery evidence | A result, failure, key, or dependency survives request completion; authorization or representation affects a value without request isolation; or V1 adds shared caching without a superseding decision and isolation proof |
| Documentation contradicts executable behavior | One authority order and one check command | A public example or spec cannot be derived from tested source |
| Package surface grows before consumers exist | Public packages require an ADR and demonstrated consumer | A package exists only to mirror an internal conceptual diagram |
| Scope exceeds maintainable capacity | Outcome gates precede tooling and adapter breadth | Work begins on optional tooling before the first vertical slice passes |
| Registry identity is unavailable | Publish nothing until names and ownership are verified | A selected public name cannot be secured consistently |
| Analyzer consumers observe stale or mixed generations | ADR 0030 requires versioned documents, workspace epochs, complete affected closure, atomic replacement, cancellation, and stale-result suppression; B7D1-B7D3 serialize retained work through batched analysis, provisional application, compiler validation, final freshness and commit/rollback, and grant derived ownership only to the newest complete generation | Diagnostics, declarations, manifests, mappings, or deletions from different epochs become jointly observable |
| Generated route replacement loses the last accepted disk set | B7C applies only an exact current diagnostic-free publication; B7D3 retains the previous or unchanged generation, uses atomic renames before destructive cleanup, distinguishes non-authoritative garbage, fault-tests partial removal, and keeps unresolved restore or cleanup state recoverable in-session and on restart | Diagnostic refusal deletes disk output, partial cleanup damages the rollback copy, mixed generations appear, or recovery guesses ownership of transaction debris |
| Complete project analysis scales superlinearly before feedback qualification | Existing document synchronization, diagnostic authority matching, deep-route ancestor validation, and deterministic graph topology/affected queues retain correctness-first full-state work; the graph queues currently re-sort arrays and are quadratic or worse on dense accepted graphs. Optimize them in a bounded slice if canonical growth triggers the risk, and measure the complete loop in V1-DX-C before any performance claim | Canonical application growth or dense graphs make edit-to-visible or edit-to-cleared latency miss the later locked feedback budget |
| Route matching cost grows with the complete route set | The generated matcher preserves accepted precedence by scanning the deterministic route set; no route-scale performance claim exists. Introduce a separately qualified generated decision structure only if canonical route growth triggers the risk | Route count makes matching a material share of server latency or fails a later locked request budget |
| Analyzer growth hardens one rigid schema | Module-owned facets are namespaced, independently versioned, bounded, and explicit about unknown/newer versions | A new framework module requires central enumeration or an unsupported facet is silently interpreted |
| Static evidence is presented as observed runtime truth | Static analyzer and runtime records remain separate facets linked only by evidence identity | Source analysis claims request ordering, authorization, streaming, cancellation, or browser outcomes |
| Development lifecycle appears correct only in direct tests | V1-DX-C requires packed canonical-app recovery, a disposable lifecycle client, and full feedback-loop timing | Stale errors survive repair, transitive artifacts lag, or obsolete work publishes in the lifecycle harness |
| Filesystem notifications are mistaken for semantic truth | B7D4 admits only contained private invalidation hints, separates raw-notification and accepted-admission identity, bounds retained paths by count and UTF-8 bytes, excludes owned output and repository metadata, converts rename/missing-name/alias/overflow ambiguity into full authoritative rescans, coalesces with bounded debounce and maximum delay, and retains one later batch for work arriving during refresh | Rename/null/duplicate/overflow events miss a change, publish twice, escape containment, retain unbounded notification input, or trigger an output loop |
| Analyzer, compiler, and server expose different generations | B7D3 serializes current analysis, provisional B7C application, stock input discovery and validation, exact installed-package mapping and manifest identity, post-validation freshness, and acceptance or rollback; B7D6 additionally excludes concurrent builds with crash-recoverable ownership, requires a matching independent final generation, validates newly added source and external compiler inputs, binds emitted imports and startup to the bounded declared production-dependency graph, accepts rollback only from an exact manifest-owned current-framework generation, and verifies output/runtime identity before production imports; B7D7 serves only a fully accepted development generation in a fresh verified child | Compiler/server reads during route replacement, a concurrent or crashed builder leaves ambiguous ownership, an external, remapped, added, or changed dependency input escapes freshness, an emitted development-only import escapes the production graph, fabricated rollback is trusted, stale compiler output publishes, or a request observes mixed ownership |
| Development reload leaks or serves mixed application generations | ADR 0033 keeps application imports out of the supervisor, freezes environment and runtime closure per generation, requires loader-before-bootstrap startup in isolated children, preserves last-good on candidate failure, and bounds switch, rollback, drain, repeated signal, and forced cleanup; B7D7's packed operating-system lifecycle proves direct/transitive/configuration/rename/deletion/burst rescans, diagnostic recovery, occupied-address refusal, graceful close, and repeated-signal cleanup | A failed candidate stops the accepted child, imports cross generations, changes supervisor environment, publishes mixed output, or leaves a watcher/compiler/server child after close |
| Retained analysis accumulates historical route-root source text | B7D2 atomically reconciles the full desired/forgotten owner set as saved records, requires exact managed saved revision, refuses open desired/forgotten buffers, and proves three still-existing disjoint roots retain only current source text | Repeated disjoint route-root changes make retained memory or reconciliation cost depend on cumulative historical files rather than current ownership |

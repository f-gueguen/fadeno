# K0 detailed plan — kill-risk evidence

K0 decides whether Fadeno's four highest-risk mechanisms are viable before V1
public APIs depend on them. Experiment code is private, disposable evidence;
results and resulting ADRs are durable.

## Entry conditions

- F0 repository checks pass from a frozen install.
- The initial repository commit and license decision are complete.
- K0-01 accepts a reproducible browser reference environment before browser
  qualification. A later experiment may add a separate versioned reference
  only through an accepted ADR that preserves historical evidence and locks
  equivalent CPU/memory limits, operating system, runtime, power policy, and
  prohibited background load before measurement.
- Each experiment has an owner, isolated directory, locked dependencies, and a
  review-approved fixture corpus before implementation results are collected.
- Gate thresholds below are changed only by a reviewed plan change made before
  the affected qualification run. Results never move their own goalposts.

## Repository layout

```text
experiments/
  morph/
    README.md
    fixtures/
    tests/
    results/<run-id>/manifest.json
  extraction/
    README.md
    fixtures/accepted/
    fixtures/rejected/
    tests/
    results/<run-id>/manifest.json
  type-spine/
    README.md
    fixtures/valid/
    fixtures/invalid/
    tests/
    results/<run-id>/manifest.json
  revalidation/
    README.md
    app/
    fixtures/
    tests/
    results/<run-id>/manifest.json
```

Each experiment README states the hypothesis, command, fixture inventory,
environment requirements, measurement method, pass/pivot threshold, and links
to its current result. Result manifests record the source commit, operating
system, architecture, runtime and browser versions, dependency lock hash,
command, warmup, repetitions, raw measurements, failures, and conclusion.

## Required commands

Each experiment PR adds one root command and includes it in the applicable
qualification workflow:

```sh
pnpm experiment:morph
pnpm experiment:extraction
pnpm experiment:type-spine
pnpm experiment:revalidation
pnpm experiment:all
```

`pnpm check` validates experiment source and fixtures. Once all K0 decisions are
immutable, `experiment:all` verifies the four retained outcomes without rerunning
one-shot qualification measurements and is required by K0-11.

## H1 threshold — preservation

Corpus:

- focused input, textarea, and contenteditable selection/caret;
- dirty text, checkbox, radio, select, and file controls;
- open disclosure, modal/non-modal dialog, and popover;
- playing/paused media position;
- document and nested-element scroll;
- structural insert, remove, reorder, and intentional replacement.

Pass requires:

1. Chromium, Firefox, and WebKit all execute every fixture.
2. CI repeats every fixture 20 times per engine; the qualification run repeats
   it 100 times per engine.
3. There are zero undeclared state-loss, focus-transfer, runtime-error, or
   unhandled-promise failures.
4. Intentional replacement occurs in 100% of its control cases, proving the
   harness can distinguish preservation from accidental non-update.
5. Failure traces identify the structural operation and before/after state.

Any engine-specific exclusion narrows the supported browser matrix and requires
an explicit ADR; it cannot be hidden as a retry.

## H2 threshold — extraction

The accepted corpus contains at least toggle, disclosure, tabs, menu, and local
counter interactions. The rejected corpus contains at least server-secret,
server-module, opaque capability, unsupported class instance, cyclic data,
dynamic import, ambient browser/server switch, unsupported async lifetime,
oversized capture, and non-deterministic closure cases.

Pass requires:

1. Every accepted fixture behaves correctly for 100 consecutive interactions.
2. Its browser module graph contains the selected handler and permitted shared
   dependencies, but no fragment renderer, server module, or component runtime.
3. No handler module is requested before the configured interaction trigger.
4. The first interaction requests at most the handler chunk and its declared
   shared dependencies; it never requests a fragment-wide hydration chunk.
5. Every rejected fixture fails at its source boundary with the expected stable
   diagnostic and no browser artifact.
6. Handler identity survives all H1 reorder and unrelated-update fixtures.

If fewer than four of the five accepted interaction classes fit without a
special-case rule, H2 narrows or pivots to explicit islands for the initial
release.

## H3 threshold — stock-TypeScript type spine

The qualification corpus contains 1,000 generated routes, including nested and
parameterized cases, plus valid and invalid link, form-field, and context
consumers.

Pass requires:

1. All valid fixtures compile and every invalid fixture reports the expected
   error at the application source location with no unexpected diagnostics.
2. Two clean generations are byte-identical.
3. Removing a route or field removes its generated type on the next run without
   leaving stale declarations.
4. On the frozen H3 environment accepted by ADR 0017, clean generator p95 is no more than 1.5
   times stock `tsc --noEmit` p95 over the same 1,000-route project, and a
   single-route incremental generator p95 is no more than 25% of its clean p95,
   measured over 20 post-warmup repetitions.
5. Stock `tsc` and a stock editor language service consume the output without a
   framework plugin.

Failure of the latency threshold narrows generator scope or invalidation before
editor-specific tooling is considered.

## H4 threshold — correctness-first revalidation

The private benchmark uses an authenticated CRUD page with six unique resources,
three duplicate reads, one mutation that affects one resource, at least 10,000
data rows, and both success and failure paths. A selective baseline revalidates
only the affected resource for comparison; it is benchmark code, not a proposed
public API.

Pass requires:

1. Zero stale observable outcomes across 10,000 randomized mutation/read/order
   cycles.
2. Each equivalent resource identity executes at most once per request.
3. On the frozen K0-01 environment, the default path's
   action-to-complete-render p95 is at most twice the selective baseline and at
   most 300 milliseconds over 1,000 post-warmup actions.
4. Process memory after 10,000 cycles is no more than 10% above the post-warmup
   baseline after forced cleanup supported by the benchmark runtime.
5. Development verification detects 100% of seeded unsafe `keeps`
   declarations without logging authorization-sensitive values.
6. The chosen comparison strategy handles values, expected errors, ordering,
   and non-cacheable results or conservatively refuses the optimization.

Failure pivots the invalidation/dependency model before public actions exist;
the benchmark is not weakened to preserve ADR 0006.

## K0 exit

K0 completes only when all four hypotheses have immutable result manifests and
an effective go, narrow, or pivot ADR; the hypothesis ledger contains no K0
claim without a result; feature scope and traceability reflect the decisions;
and a detailed V1 plan is reviewed against the accepted architecture.

K0 exited through K0-11 and ADR 0021. The implementation-ready continuation is
the [V1 detailed plan](v1.md).

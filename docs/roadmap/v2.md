# V2 detailed plan — browser enhancement

V2 adds an optional browser delivery path to the published native application.
It delivers the same server-owned application outcome and does not create a
second router, action model, resource model, or state authority. Every enhanced
outcome must remain equivalent to the native link or form outcome and must fall
back safely when enhancement cannot own the work.

## Entry conditions

- A0-10 is merged and `@fadeno/framework@0.1.0-alpha.1` is independently
  installable and verified from the public registry.
- ADR 0014's narrowed structural-preservation result and the complete K0-04
  three-engine evidence remain immutable inputs.
- V1's public route, resource, action, session, build, development, test, and
  deployment workflows pass through the canonical application.
- DG-V2-01 remains open and blocks ENH-01 implementation. V2-01 may gather and
  decide its evidence; no earlier slice may invent the patch contract.

## Delivery checkpoints

- **Protocol checkpoint — V2-01:** one accepted ADR owns patch identity, scroll
  boundary, ordering, redirects, errors, recovery, cache policy, and version
  negotiation with versioned executable fixtures.
- **Package-boundary checkpoint — V2-01A:** one separate accepted ADR, backed
  by a disposable packed consumer, owns the optional browser entrypoint before
  any implementation crosses ADR 0024's private boundary.
- **First enhanced navigation — V2-04:** the canonical application follows one
  link through the optional browser path and reaches the same URL, document,
  history, focus, and server state as native navigation. Before V2-08, every
  update boundary whose browser- or user-owned state cannot be preserved is
  refused before interception and follows the native path.
- **Enhanced action checkpoint — V2-07:** the authenticated CRUD flow submits
  through the same public action with pending, cancellation, redirect,
  validation, revalidation, and non-duplicating recovery evidence.
- **Usable V2 checkpoint — V2-09:** the full canonical application passes native
  and enhanced equivalence plus preservation, ordering, interruption, and
  recovery in Chromium, Firefox, and WebKit.
- **Qualification checkpoint — V2-11:** executable examples, generated guidance,
  separate security hardening, accessibility/screen-reader qualification,
  final hardened-byte runtime-cost evidence, clean installation, and
  upgrade/rollback qualification are complete without consuming reviewed
  release intent or changing the measured browser artifact.
- **V2 release — V2-12:** one mechanical slice consumes the reviewed Changesets,
  advances the alpha prerelease, creates immutable release artifacts, publishes
  through the trusted transport, and verifies the exact registry result.

## Boundaries retained throughout V2

- Native links and forms remain the correctness baseline and work without
  JavaScript. Enhancement is optional and may refuse before interception.
- Stock TypeScript owns ordinary TypeScript/JSX parsing, typing, completion,
  navigation, formatting, and refactoring.
- The private analyzer remains tool-neutral and private. V2 introduces no
  editor product or public analyzer schema.
- Static analysis does not fabricate observed navigation, authorization,
  timing, cancellation, history, scroll, or browser-preservation facts.
- The update format is bounded and versioned but does not become a general
  application command channel.
- Islands remain V3. V2 may preserve opaque mounted identity in conformance
  fixtures but does not introduce island authoring or lifecycle APIs.
- Optimistic mutation authoring, live-resource transport, component bridges,
  and additional adapters remain deferred.

Every V2 PR declares its release impact. Every slice that changes the
publishable package's user-visible behavior carries exactly one pending
Changeset with changelog-ready text and explicit semantic-version intent.
Decision-, qualification-, evidence-, or documentation-only work states why no
Changeset is required. V2-11 does not collect release intent that belonged to
an earlier package-changing PR. V2-12 is the separate mechanical release slice:
it consumes only reviewed intent and introduces no unrelated behavior.

Every user-observable slice extends the canonical application and its isolated
scenario harness with executable success, deliberate failure or refusal,
human and normalized machine output, correction when safe, ownership/causal
flow inspection, and stale-state recovery. Examples use current packed public
entrypoints, assert behavior, normalize unstable values, and run in the local
merge gate.
